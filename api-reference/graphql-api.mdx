The GraphQL API provides flexible, composable query primitives for querying 929M+ Solana transaction instruction records. Unlike REST endpoints with predefined use cases, GraphQL lets you build exactly the queries you need.

## Endpoint

```
POST /graphql
```

**Base URL:** `https://api.solixdb.xyz/graphql`

## Authentication

The API is **publicly accessible** and does not require authentication. Rate limiting is applied per IP address based on query complexity.

<Info>
  For details on rate limiting and complexity scoring, see our [Rate Limiting](/rate-limiting) and [Query Complexity](#query-complexity) sections.
</Info>

## Custom Scalars

The API uses several custom scalar types:

| Scalar | Description | Format | Example |
|--------|-------------|--------|---------|
| `Date` | Date scalar type | YYYY-MM-DD | `"2025-01-15"` |
| `Signature` | Solana transaction signature | Base58 encoded string (64-90 chars) | `"5VERv8NMxzbPDohNpJhHopN2C9R4G5GaPevYf5hLJ8Z7"` |
| `ProgramID` | Solana program ID | Base58 encoded string (32-44 chars) | `"JUP6LkbZbjS1jKKwapdHNy74zcZ3tLUZoi5QNyVTaV4"` |
| `BigInt` | Long integer type | Serialized as string | `"1234567890123456789"` |

## Queries

### transactions

Flexible transactions query with filters, aggregations, grouping, sorting, and pagination.

**Signature:**
```graphql
transactions(
  filters: TransactionFilters
  groupBy: [GroupByDimension!]
  metrics: [AggregationMetric!]
  sort: SortInput
  pagination: PaginationInput
): TransactionConnection!
```

**Arguments:**

| Argument | Type | Required | Description |
|----------|------|----------|-------------|
| `filters` | `TransactionFilters` | No | Filter criteria for transactions |
| `groupBy` | `[GroupByDimension!]` | No | Dimensions to group by (enables aggregation) |
| `metrics` | `[AggregationMetric!]` | No | Aggregation metrics to calculate |
| `sort` | `SortInput` | No | Sort order for results |
| `pagination` | `PaginationInput` | No | Cursor-based pagination |

**Example: Basic Query**

<CodeGroup>
```graphql
query {
  transactions(
    filters: {
      protocols: ["pump_fun", "pump_amm"]
      dateRange: { start: "2025-01-01", end: "2025-01-31" }
    }
    pagination: { first: 100 }
  ) {
    edges {
      node {
        signature
        slot
        protocolName
        fee
        computeUnits
      }
      cursor
    }
    pageInfo {
      hasNextPage
      endCursor
    }
  }
}
```

```bash curl
curl -X POST https://api.solixdb.xyz/graphql \
  -H "Content-Type: application/json" \
  -d '{
    "query": "query { transactions(filters: { protocols: [\"pump_fun\", \"pump_amm\"], dateRange: { start: \"2025-01-01\", end: \"2025-01-31\" } }, pagination: { first: 100 }) { edges { node { signature slot protocolName fee computeUnits } cursor } pageInfo { hasNextPage endCursor } } }"
  }'
```

<Info>
  **Filter Ordering:** Filters are automatically applied in optimal order for performance:
  1. `signature =` (bloom filter, super selective)
  2. `program_id IN` (bloom filter, very selective)
  3. `date BETWEEN` (partition pruning)
  4. `slot BETWEEN` (somewhat selective)
  5. `protocol_name IN` (bloom filter, less selective)
  6. Everything else
</Info>

## Pagination

The API uses cursor-based pagination for efficient large result sets. Cursors are composite `(slot, signature)` values encoded as base64 strings.

**Pagination Rules:**
- Queries returning >10k rows: **FORCE cursor pagination**
- Max 1000 rows per page
- Aggregations capped at 10k groups
- Use `pageInfo.hasNextPage` to check for more results
- Use `pageInfo.endCursor` for next page

**Example: Paginated Query**

<CodeGroup>
```graphql
query GetTransactions($first: Int, $after: String) {
  transactions(
    filters: {
      protocols: ["pump_fun"]
      dateRange: { start: "2025-01-01", end: "2025-01-31" }
    }
    pagination: { first: $first, after: $after }
  ) {
    edges {
      node {
        signature
        slot
        protocolName
        fee
      }
      cursor
    }
    pageInfo {
      hasNextPage
      hasPreviousPage
      startCursor
      endCursor
    }
    totalCount
  }
}
```

```javascript JavaScript
async function fetchAllTransactions() {
  let allTransactions = [];
  let hasNextPage = true;
  let cursor = null;
  
  while (hasNextPage) {
    const query = `
      query GetTransactions($first: Int, $after: String) {
        transactions(
          filters: {
            protocols: ["pump_fun"]
            dateRange: { start: "2025-01-01", end: "2025-01-31" }
          }
          pagination: { first: 1000, after: $after }
        ) {
          edges {
            node {
              signature
              slot
              protocolName
              fee
            }
            cursor
          }
          pageInfo {
            hasNextPage
            endCursor
          }
        }
      }
    `;
    
    const response = await fetch('https://api.solixdb.xyz/graphql', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        query,
        variables: { first: 1000, after: cursor }
      }),
    });
    
    const data = await response.json();
    const connection = data.data.transactions;
    
    allTransactions.push(...connection.edges.map(e => e.node));
    hasNextPage = connection.pageInfo.hasNextPage;
    cursor = connection.pageInfo.endCursor;
  }
  
  return allTransactions;
}
```
</CodeGroup>

## Query Complexity

Query complexity is calculated based on:
- **Base cost** = `estimated_rows / 10000`
- **GROUP BY multiplier** = `2^dimensions`
- **Aggregation cost** = `+10% per aggregation`
- **Final score** = `base_cost * group_by_multiplier * (1 + aggregation_cost)`

**Complexity Tiers:**

| Complexity | Rate Limit (per minute) |
|------------|-------------------------|
| < 50       | 200                     |
| < 100      | 100                     |
| < 200      | 50                      |
| < 500      | 20                      |
| < 1000     | 10                      |
| ≥ 1000     | Rejected                |

<Warning>
  Always check complexity before executing expensive queries using the `queryComplexity` query.
</Warning>

## Caching

The API implements adaptive caching with real-time blockchain data invalidation:

- **Hot queries** (>5 hits): 1 hour cache
- **Recent data** (<24h): 5 min cache
- **Historical data**: 24 hour cache
- **Aggregations**: 30 min cache
- **Real-time invalidation**: Checks for new blockchain data every 60s

Cache hit rate is typically >70% for historical queries.

## Performance

**Expected Response Times:**
- Simple queries: <100ms p95
- Complex queries: <1s p95
- Aggregations: <2s p95

**Concurrency:**
- Handles 1000+ concurrent requests
- Connection pool auto-scales from 20-200 connections

## Error Handling

GraphQL errors follow the standard GraphQL error format:

```json
{
  "errors": [
    {
      "message": "Query complexity exceeds limit",
      "extensions": {
        "code": "COMPLEXITY_EXCEEDED",
        "complexity": 1200,
        "limit": 1000
      }
    }
  ],
  "data": null
}
```

Common error codes:
- `COMPLEXITY_EXCEEDED` - Query complexity >1000
- `PAGINATION_REQUIRED` - Query returns >10k rows without pagination
- `INVALID_FILTER` - Invalid filter value
- `RATE_LIMIT_EXCEEDED` - Rate limit exceeded
- `VALIDATION_ERROR` - Input validation failed

For more details, see our [Error Handling](/error-handling) guide.
