The API implements **complexity-based rate limiting** to ensure fair usage and maintain service quality. Rate limits are calculated based on query complexity, not just request count.

## How It Works

Rate limiting uses a **logarithmic tier system** based on query complexity:

| Complexity Score | Rate Limit (per minute) |
|------------------|-------------------------|
| < 50             | 200                     |
| < 100            | 100                     |
| < 200            | 50                      |
| < 500            | 20                      |
| < 1000           | 10                      |
| ≥ 1000           | Rejected                |

### Complexity Calculation

Query complexity is calculated as:

```
base_cost = estimated_rows / 10000
group_by_multiplier = 2^dimensions
aggregation_cost = 1 + (0.1 * number_of_aggregations)
final_score = base_cost * group_by_multiplier * aggregation_cost
```

**Example:**
- Query with 100k estimated rows, 2 group by dimensions, 3 aggregations:
  - Base cost: 100000 / 10000 = 10
  - Group by multiplier: 2^2 = 4
  - Aggregation cost: 1 + (0.1 * 3) = 1.3
  - Final score: 10 * 4 * 1.3 = **52** (tier: < 100, limit: 100/min)

<Info>
  Use the `queryComplexity` query to check complexity before executing expensive queries. See [GraphQL API Reference](/api-reference/graphql-api#querycomplexity).
</Info>

## Rate Limit Headers

Every API response includes rate limit information in the headers:

```
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 95
X-RateLimit-Reset: 2025-07-20T12:01:00Z
Retry-After: 5
```

### Header Descriptions

- **X-RateLimit-Limit:** Maximum complexity allowed in the current window
- **X-RateLimit-Remaining:** Remaining complexity budget in the current window
- **X-RateLimit-Reset:** ISO 8601 timestamp when the rate limit window resets
- **Retry-After:** Seconds to wait before retrying (only present on 429 responses)

## Sliding Window

Rate limiting uses a **sliding window** approach:
- Tracks total complexity used in the last 60 seconds
- Each query consumes complexity from your budget
- Budget resets as queries age out of the window

**Example:**
- At 12:00:00, you execute a query with complexity 50
- At 12:00:30, you execute another query with complexity 30
- At 12:01:00, the first query (50) ages out, leaving 30 in the window
- Your remaining budget = limit - 30

## Rate Limit Exceeded

When you exceed the rate limit, you'll receive a `429 Too Many Requests` response:

**REST API:**
```json
{
  "error": "Too Many Requests",
  "message": "Rate limit exceeded. Complexity budget exhausted."
}
```

**GraphQL:**
```json
{
  "errors": [
    {
      "message": "Rate limit exceeded",
      "extensions": {
        "code": "RATE_LIMIT_EXCEEDED",
        "retryAfter": 5
      }
    }
  ],
  "data": null
}
```

**Status Code:** `429 Too Many Requests`

## Handling Rate Limits

### Check Complexity Before Execution

Use the `queryComplexity` query to estimate cost:

```graphql
query {
  queryComplexity(
    filters: {
      dateRange: { start: "2025-01-01", end: "2025-01-31" }
      protocols: ["pump_fun"]
    }
    groupBy: [PROTOCOL, HOUR]
    metrics: [COUNT, AVG_FEE]
  ) {
    score
    estimatedRows
    recommendations
  }
}
```

### Exponential Backoff

Implement exponential backoff when you receive a 429 response:

```javascript
async function makeRequest(url, options, retries = 3) {
  for (let i = 0; i < retries; i++) {
    try {
      const response = await fetch(url, options);
      
      if (response.status === 429) {
        const retryAfter = response.headers.get('Retry-After');
        const waitTime = retryAfter 
          ? parseInt(retryAfter) * 1000 
          : Math.pow(2, i) * 1000; // Exponential backoff
        
        await new Promise(resolve => setTimeout(resolve, waitTime));
        continue;
      }
      
      return response;
    } catch (error) {
      if (i === retries - 1) throw error;
      await new Promise(resolve => setTimeout(resolve, Math.pow(2, i) * 1000));
    }
  }
}
```

### Respect Rate Limit Headers

Monitor complexity budget and adjust request rate:

```javascript
const response = await fetch(url, options);
const remaining = parseInt(response.headers.get('X-RateLimit-Remaining'));
const limit = parseInt(response.headers.get('X-RateLimit-Limit'));

// If using more than 80% of budget, slow down
if (remaining < limit * 0.2) {
  await new Promise(resolve => setTimeout(resolve, 2000));
}
```

### Optimize Query Complexity

Reduce complexity to stay within limits:

1. **Add filters** to reduce estimated rows:
   ```graphql
   # High complexity (large date range)
   transactions(filters: { dateRange: { start: "2024-01-01", end: "2025-01-31" } })
   
   # Lower complexity (smaller date range)
   transactions(filters: { dateRange: { start: "2025-01-01", end: "2025-01-31" } })
   ```

2. **Reduce group by dimensions**:
   ```graphql
   # Complexity multiplier: 2^3 = 8
   groupBy: [PROTOCOL, HOUR, INSTRUCTION_TYPE]
   
   # Complexity multiplier: 2^2 = 4
   groupBy: [PROTOCOL, HOUR]
   ```

3. **Use pagination** for large result sets:
   ```graphql
   # Forces pagination if >10k rows
   transactions(pagination: { first: 1000 })
   ```

4. **Limit aggregations**:
   ```graphql
   # Lower cost
   metrics: [COUNT, AVG_FEE]
   
   # Higher cost
   metrics: [COUNT, AVG_FEE, P50_FEE, P95_FEE, P99_FEE, SUM_FEE, ...]
   ```

### Caching

Cache responses to reduce API calls:

```javascript
const cache = new Map();

async function getCachedData(key, fetcher, ttl = 60000) {
  const cached = cache.get(key);
  if (cached && Date.now() - cached.timestamp < ttl) {
    return cached.data;
  }
  
  const data = await fetcher();
  cache.set(key, { data, timestamp: Date.now() });
  
  return data;
}
```

<Info>
  The API implements adaptive caching:
  - Hot queries (>5 hits): 1 hour cache
  - Recent data (<24h): 5 min cache
  - Historical data: 24 hour cache
  - Aggregations: 30 min cache
</Info>

## Export Mutations

Export dataset mutations have separate rate limits:

- **Limit:** 5 exports per hour per IP
- **Complexity:** Exports are processed in background, complexity applies to job creation

```graphql
mutation {
  exportDataset(config: { ... }) {
    id
    status
  }
}
```

## Toggle-able Rate Limiting

Rate limiting can be disabled server-side by setting `ENABLE_RATE_LIMIT=false`. This is useful for:
- Development environments
- Internal services
- High-trust clients

<Warning>
  Rate limiting is enabled by default in production. Contact support if you need custom rate limits or disabling for your use case.
</Warning>

## Examples

### Checking Complexity

```javascript
async function checkComplexity(filters, groupBy, metrics) {
  const query = `
    query {
      queryComplexity(
        filters: $filters
        groupBy: $groupBy
        metrics: $metrics
      ) {
        score
        estimatedRows
        recommendations
      }
    }
  `;
  
  const response = await fetch('https://api.solixdb.xyz/graphql', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      query,
      variables: { filters, groupBy, metrics }
    }),
  });
  
  const data = await response.json();
  const complexity = data.data.queryComplexity;
  
  if (complexity.score >= 1000) {
    console.warn('Query will be rejected:', complexity.recommendations);
    return false;
  }
  
  return true;
}
```

### Rate Limit Aware Request

```javascript
async function makeRateLimitAwareRequest(query, variables) {
  const maxRetries = 3;
  
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    const response = await fetch('https://api.solixdb.xyz/graphql', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ query, variables }),
    });
    
    if (response.status === 429) {
      const retryAfter = response.headers.get('Retry-After');
      const waitTime = retryAfter 
        ? parseInt(retryAfter) * 1000 
        : Math.pow(2, attempt) * 1000;
      
      console.log(`Rate limited. Retrying after ${waitTime}ms...`);
      await new Promise(resolve => setTimeout(resolve, waitTime));
      continue;
    }
    
    if (!response.ok) {
      throw new Error(`Request failed: ${response.statusText}`);
    }
    
    return await response.json();
  }
  
  throw new Error('Max retries exceeded');
}
```
